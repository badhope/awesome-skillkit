## 报告漏洞

我们非常重视 AI-SKILL 的安全性。如果你发现了安全漏洞，请
负责任地报告。

**请勿在公开 GitHub Issue 中报告安全漏洞。**

### 报告流程

1. 将详细信息通过邮件发送给仓库页面上列出的安全联系人
2. 邮件中请包含漏洞的详细描述：
   - 受影响的组件及版本
   - 复现步骤
   - 潜在影响
   - 建议的修复方案（若有）
3. 在修复完成前给我们留出处理时间，再进行任何公开披露

### 响应时效

| 阶段               | 预期时间             |
|--------------------|----------------------|
| 初次确认           | 48 小时内            |
| 确认与评估         | 5 个工作日内         |
| 修复开发与测试     | 14 个工作日内        |
| 协同披露           | 修复发布后            |

严重漏洞会被相应优先处理。

### 你将获得

- 48 小时内收到你的报告确认
- 我们会在整个过程中与你同步进展
- 在发布说明中为你署名（除非你希望保持匿名）
- 如适用，会申请 CVE 标识符

## 安全最佳实践

### 给部署者

1. **始终修改默认密钥** —— 生产环境不要使用示例 JWT 密钥。请生成强密钥：
   ```bash
   openssl rand -hex 32
   ```
   当 `JWT_SECRET_KEY` 缺失、长度不足 32 字符，或与某个已知的弱默认值相同时，
   应用**拒绝在生产环境启动**（`DEBUG=false`）。在 `DEBUG=true` 模式下，
   系统会为每个进程生成一个临时随机密钥并打印警告日志，这种方式让开发体验
   无摩擦，但**不**适用于生产。

2. **安全地引导首位管理员** —— 在首次启动前在 `.env` 中设置 `ADMIN_PASSWORD`
   （≥ 12 字符），让 `app.core.seed` 能创建初始超级用户；或运行专用 CLI：
   ```bash
   ADMIN_PASSWORD="$(openssl rand -base64 18)" \\
   ADMIN_EMAIL="ops@yourdomain.com" \\
   ADMIN_USERNAME="ops" \\
   python -m app.scripts.create_admin
   ```
   如果两条路径都没有走，应用在启动时会打印一行 CRITICAL 日志并**跳过**管理员
   植入 —— 因此每个全新的数据库都需要运维显式操作后才能登录后台。

3. **使用 TLS** —— 始终通过反向代理（Nginx、Traefik、Caddy）并启用 TLS 终止

4. **限制 CORS 源** —— 将 `BACKEND_CORS_ORIGINS` 设置为只包含你的前端域名。
   因为 API 使用了 `allow_credentials=true`，所以不支持通配符来源。

5. **启用速率限制** —— 合理配置 `RATE_LIMIT_DEFAULT` 与 `RATE_LIMIT_WINDOW`

6. **及时更新依赖** —— 定期执行 `poetry update` 和 `npm update`

7. **数据库安全** —— 使用强密码、限制网络访问、启用 SSL 连接。
   `docker-compose.yml` 中的 `POSTGRES_PASSWORD` 取自 `.env`，若未设置则
   故意留空 —— 让容器在启动时失败，而不是带着一个已知的弱默认值。

8. **环境隔离** —— 为开发、预发、生产使用不同的 `.env` 文件

### 给贡献者

1. **不要提交密钥** —— API 密钥、密码、令牌绝不能提交进仓库
2. **`.env.example` 仅作模板**；真实值放进 `.env`（已在 git 忽略中）
3. **校验输入** —— 所有用户输入必须在服务端校验
4. **清理输出** —— 防止 XSS，对用户生成内容做清理
5. **最小权限原则** —— 数据库用户只授予最小必要权限
6. **审阅依赖** —— 在新增依赖前检查已知漏洞

## 漏洞披露策略

AI-SKILL 遵循协同披露模型：

1. 报告者私下提交漏洞
2. 维护者验证并评估漏洞
3. 开发并测试修复
4. 发布安全更新
5. 在用户有合理时间升级后进行公开披露

我们请求你在我们处理完之前不要公开披露漏洞。我们的目标是在
14 天内解决严重问题，并会与你协调披露时间。

## 安全特性

AI-SKILL 实现了多项安全措施：

- **认证**：JWT，支持 access / refresh 双令牌轮换
- **授权**：基于角色的访问控制（RBAC）
- **输入校验**：所有 API 输入都通过 Pydantic 模式校验
- **速率限制**：可按端点与全局配置
- **CORS**：可配置的跨域资源共享策略
- **密码哈希**：bcrypt，使用合适的工作因子
- **密码策略**：至少 8 字符，包含大写、小写与数字；弱密码黑名单
- **安全响应头**：`SecurityHeadersMiddleware` 添加 HSTS（仅生产）、
  `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、
  `Permissions-Policy`、严格 `Content-Security-Policy`，以及一组
  `Cross-Origin-*` 隔离头。同时清理 `Server` 与 `X-Powered-By` 头，
  避免被指纹识别。
- **启动期密钥校验**：生产环境在没有 32+ 字符、且不在弱默认黑名单中的
  `JWT_SECRET_KEY` 时拒绝启动。`ADMIN_PASSWORD` 在生产环境的种子植入中
  也遵循同一策略。
- **HTTPS**：推荐在反向代理层做 TLS 终止
- **审计日志**：所有认证与修改事件均被记录
- **依赖扫描**：CI 流水线中自动化进行漏洞扫描
