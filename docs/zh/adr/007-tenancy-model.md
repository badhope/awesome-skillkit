# ADR 007 — v1 单租户，v1.2 多租户

- **状态**：已采纳
- **日期**：2026-06-01

## 背景

许多 "AI 技能" 平台从第一天就主打多租户组织。但我们**故意**不这么做。

## 决策

**v1** 是单租户：一份部署 = 一个组织。**v1.2** 会加入 `organizations` 表与
`memberships` 联结表，从而支持多租户部署。

## 依据

- 多租户意味着行级安全、组织切换 UI、按组织计费、按组织限流。每一项都是不小的测试面。
- 大多数自托管用户为自己的团队部署一份实例。Day-1 就强加多租户数据建模
  会拖慢这条路径。
- v1.2 可以在不重写公共 REST 接口的前提下，向所有现有表加一个
  `organization_id` 外键。

## 后果

- v1 的数据模型**不**感知租户。在 v1.2 增加 `organization_id` 是一次前向兼容的迁移。
- v1.2 的认证模型会在 JWT 中增加一个 org claim。
- 定价方面（如果加入的话）：v1 按部署收费，v1.2 按组织收费。
