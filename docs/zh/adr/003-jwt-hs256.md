# ADR 003 — 选用 HS256 JWT 而非 RS256

- **状态**：已采纳
- **日期**：2026-06-01

## 背景

我们需要无状态、带签名的身份令牌。两个主流选择是 HMAC（HS256，单一共享密钥）
和 RSA / ECDSA（RS256 / ES256，公私钥对）。

## 决策

v1 使用 **HS256 + 单一共享密钥**。

## 依据

- 单体自托管服务 —— 没有任何第二个服务需要在不持有签名密钥的情况下验证令牌。
- HS256 更快、更简单，轮换也更方便。
- 刷新令牌轮换由现有的 `/auth/refresh` 流程支持。先前描述的"基于 Redis
  的 JTI 黑名单"**只是规划，尚未实现**（截至本 ADR 落款日期）。

## 何时需要重评

当我们加入一个独立的"agent 执行器"或"边缘 worker"服务，必须在不持有
签名密钥的前提下验证令牌时，会切换到 RS256，并通过 JWKS 端点发布公钥。

## 后果

- 签名密钥（`JWT_SECRET_KEY`）是系统中最重要的一把密钥。生产环境在密钥
  不足 32 字符时拒绝启动。
- 密钥在进程启动时加载一次；轮换需要各后端副本协同重启。
